Connecting

The usual form is psql -h HOST -p PORT -U USER -d DATABASE; any flag you leave out falls back to an environment variable, then a default.

FlagMeaningDefault if omitted
-h hostServer hostname or IPLocal Unix socket
-p 5432Port5432
-U userDatabase role (user)Your OS username
-d dbnameDatabase to openSame as the user name
-WForce a password promptPrompts only if the server asks
-c "SQL"Run one command and exit—
-f file.sqlRun a script file and exit—

Connection string (URI) form, handy for copy-paste:

psql "postgresql://user:password@host:5432/dbname?sslmode=require"

Environment variables let you skip the flags: PGHOST, PGPORT, PGUSER, PGDATABASE, PGPASSWORD (avoid in shared shells).

To avoid typing passwords, add a line to ~/.pgpass (Windows: %APPDATA%\postgresql\pgpass.conf) and run chmod 600 ~/.pgpass:

host:port:database:user:password

Already inside psql? Switch with \c dbname or \c dbname user host port. \conninfo shows where you are connected.

Survival basics

psql takes two kinds of input: SQL statements, which run only when you type a semicolon, and backslash meta-commands, which run immediately with no semicolon.

CommandWhat it does
\q (or Ctrl+D)Quit psql
\?List all backslash commands
\hList SQL commands; \h CREATE TABLE shows syntax for one
\rClear the query buffer (abandon a half-typed statement)
Ctrl+CCancel a running query or the current line
\eOpen the last query in your editor, run it on save
\gRe-run the last query
\sShow command history
\! cmdRun a shell command, e.g. \! clear

Read the prompt to see what psql is waiting for:

PromptMeaning
mydb=>Ready; you are a normal user
mydb=#Ready; you are a superuser — be careful
mydb->Statement not finished; you probably forgot the ;
mydb'> or mydb">Unclosed quote; type the closing quote
mydb(>Unclosed parenthesis
mydb=*>Inside an open transaction (PG 13+)
mydb=!>Transaction failed; run ROLLBACK;

If a query prints a long result and leaves you at a : or (END) screen, you are in the pager: press q to get back.

Exploring a database

The \d family describes what exists; add + for more detail (sizes, comments) and a pattern to filter, e.g. \dt sales.* or \dt *order*.

CommandShows
\lAll databases
\dnSchemas in the current database
\dtTables (in schemas on your search path)
\dt *.*Tables in every schema, including system ones
\d tablenameColumns, types, indexes, constraints, triggers of one table
\d+ tablenameSame plus storage, size, and column comments
\dv / \dmViews / materialized views
\diIndexes
\dsSequences
\dfFunctions; \df+ name shows source
\duRoles (users) and their attributes
\dp tablenameAccess privileges (who can SELECT, INSERT, …)
\dxInstalled extensions
\sf funcnamePrint a function's definition
\sv viewnamePrint a view's definition

Useful context checks:

SELECT current_database(), current_user, version();
SHOW search_path;   -- which schemas unqualified names resolve to

If \dt shows "Did not find any relations", the tables are probably in a schema not on your search path: try \dt *.* or \dn, then SET search_path TO myschema, public;.

Everyday queries

These cover most quick look-ups; always add LIMIT when peeking at an unfamiliar table.

-- Peek at data
SELECT * FROM orders LIMIT 10;
SELECT count(*) FROM orders;
SELECT * FROM orders ORDER BY created_at DESC LIMIT 5;

-- Filter, group, distinct
SELECT status, count(*) FROM orders GROUP BY status ORDER BY 2 DESC;
SELECT DISTINCT country FROM customers;
SELECT * FROM customers WHERE email ILIKE '%@example.com';  -- case-insensitive

-- Dates
SELECT * FROM orders WHERE created_at >= now() - interval '7 days';
SELECT date_trunc('day', created_at) AS day, count(*) FROM orders GROUP BY 1 ORDER BY 1;

-- Find a column anywhere
SELECT table_schema, table_name, column_name
FROM information_schema.columns
WHERE column_name ILIKE '%email%';

-- Table sizes, largest first
SELECT relname, pg_size_pretty(pg_total_relation_size(relid)) AS size
FROM pg_catalog.pg_statio_user_tables
ORDER BY pg_total_relation_size(relid) DESC LIMIT 10;

-- Database size
SELECT pg_size_pretty(pg_database_size(current_database()));

-- What is running right now
SELECT pid, usename, state, now() - query_start AS runtime, left(query, 80)
FROM pg_stat_activity WHERE state <> 'idle' ORDER BY runtime DESC;

-- Stop a runaway query (cancel first; terminate kills the connection)
SELECT pg_cancel_backend(12345);
SELECT pg_terminate_backend(12345);

-- Explain a slow query
EXPLAIN ANALYZE SELECT ...;   -- note: ANALYZE really runs it

Output formatting

\x auto fixes the most common annoyance — wide rows wrapping into an unreadable mess — by switching to one-column-per-line display when a row won't fit.

CommandEffect
\xToggle expanded (vertical) display
\x autoExpanded only when rows are too wide
\timingShow how long each query took
\pset null '∅'Show NULLs visibly instead of as blank
\pset pager offNever use the pager (on / always also valid)
\pset format csvPrint CSV (PG 12+); also aligned, unaligned, html, wrapped
\aToggle aligned / unaligned output
\tToggle headers and row count (tuples only)
\pset border 2Draw full table borders
\watch 5Re-run the last query every 5 seconds (Ctrl+C to stop)

To make settings stick, put them in ~/.psqlrc:

\set QUIET 1
\x auto
\timing on
\pset null '∅'
\set HISTCONTROL ignoredups
\set ON_ERROR_ROLLBACK interactive
\unset QUIET

From the shell, psql -A -t -c "SELECT ..." prints bare values with no headers or padding, which is handy in scripts.

Import, export and scripts

Use \copy (with the backslash) rather than SQL COPY: \copy reads and writes files on your machine with your permissions, while COPY uses the server's filesystem and needs special privileges.

-- Export a table or query to CSV with a header row
\copy orders TO 'orders.csv' WITH (FORMAT csv, HEADER)
\copy (SELECT id, total FROM orders WHERE total > 100) TO 'big_orders.csv' CSV HEADER

-- Import CSV into an existing table (columns must line up)
\copy orders (id, customer_id, total) FROM 'orders.csv' WITH (FORMAT csv, HEADER)

\copy must fit on one line and takes no trailing semicolon.

CommandWhat it does
\i file.sqlRun a SQL script from inside psql
\ir file.sqlSame, path relative to the current script
\o out.txtSend all following output to a file; \o alone stops
\w file.sqlSave the current query buffer to a file
\gxRun the query with expanded output, once
\g out.txtRun the query and write just its result to a file

From the shell:

psql -d mydb -f script.sql                     # run a script
psql -d mydb -v ON_ERROR_STOP=1 -f script.sql  # stop at the first error
psql -d mydb -c "SELECT 1" --csv > out.csv      # one query to CSV (PG 12+)
pg_dump -d mydb -f backup.sql                   # full backup as SQL
pg_dump -d mydb -t orders -f orders.sql         # one table only
psql -d newdb -f backup.sql                     # restore a plain SQL dump

Transactions and safety

psql autocommits by default: every UPDATE or DELETE is permanent the moment it finishes, so wrap risky changes in a transaction and check before committing.

BEGIN;
UPDATE customers SET status = 'inactive' WHERE last_login < '2024-01-01';
-- psql reports "UPDATE 342" — is that the number you expected?
SELECT count(*) FROM customers WHERE status = 'inactive';
COMMIT;     -- keep it
-- or
ROLLBACK;   -- undo everything since BEGIN

  • Run the WHERE clause as a SELECT count(*) first, then turn it into the UPDATE or DELETE.

  • After any error inside a transaction, every later statement fails until you ROLLBACK. \set ON_ERROR_ROLLBACK interactive lets you fix a typo and carry on instead.

  • \set AUTOCOMMIT off makes psql open a transaction automatically, so nothing sticks until you COMMIT.

  • SET default_transaction_read_only = on; makes the session read-only when you only mean to look.

  • Don't leave a transaction open and walk away: it holds locks and can block other users. Check for * in the prompt.

  • DDL (CREATE, ALTER, DROP TABLE) is transactional in Postgres, so it can be rolled back too; TRUNCATE can as well. DROP DATABASE and VACUUM cannot run in a transaction.

Gotchas for MySQL and other DB users

Most confusion comes from quoting and case rules, so check these first when something "doesn't exist".

You might tryIn Postgres / psql
SHOW DATABASES;\l
USE mydb;\c mydb
SHOW TABLES;\dt
DESCRIBE t;\d t
SHOW PROCESSLIST;SELECT * FROM pg_stat_activity;
"text" for strings'text' — double quotes mean an identifier (column/table name)
`backticks` for names"double quotes"
AUTO_INCREMENTGENERATED ALWAYS AS IDENTITY (or older SERIAL)
LIMIT 10, 20LIMIT 20 OFFSET 10
IFNULL(a, b)COALESCE(a, b)
exit\q (PG 11+ also accepts exit and quit)

  • Unquoted names are folded to lowercase: SELECT * FROM Users looks for users. A table created as "Users" must always be written "Users".

  • LIKE is case-sensitive; use ILIKE for case-insensitive matching.

  • String concatenation is a || b (or concat(a, b)); || is not OR.

  • NULL = NULL is not true; use IS NULL / IS DISTINCT FROM.

  • "Role does not exist" on connect usually means you didn't pass -U and psql used your OS username.

  • "Peer authentication failed" means local connections are tied to OS users; try -h localhost or sudo -u postgres psql.
